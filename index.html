1. Goal

Prove on live infrastructure, with a real production feed, that Boomi MFT can carry a scheduled file transfer across both trust boundaries the platform must serve, delivered as configuration rather than as a new build. Nothing else.

The MVP closes with a go, go-with-conditions or no-go recommendation backed by an auditable evidence pack. It answers five questions and no others:

  1. Can Boomi MFT move a file internal to internal without a bespoke component?
  2. Can the same engine, plus one more configuration row, move a file internal to external to another government department?
  3. Do the security controls for an OFFICIAL feed holding personal data hold, with no waiver?
  4. Will Service Operations accept the flow into support on the evidence produced?
  5. What is the measured onboarding effort, split between configuration and waiting?
Not in the MVP: cost comparison against the incumbent, target operating model, self-service portal, throughput at scale, or decommissioning UTM, the IF server or SDES. Claims of that kind would not be supportable by this evidence.

2. Candidate

ADR.040 is the only feed identified that contains both required patterns in a single business flow, with one dataset, one owner community and one test cycle. One onboarding exercise yields evidence for both cases.

Why it was chosen, and its one weakness

  • Dual-pattern in one feed, so the calendar cost of proving the platform halves.
  • Trivial volume, so the MVP tests correctness and control rather than throughput, which is the right thing to test first.
  • Removing the insecure hop is a security benefit that stands independent of the platform decision.
  • Both endpoints are already in production, so nothing is gated on a new system.
  • Weakness, stated plainly: a quarterly feed gives one natural run inside any sensible window. Controlled replay carries the volume of evidence; the single natural run carries the realism. Reviewers must not read replay evidence as production-cycle evidence.

3. Target state

Boomi MFT owns the two boundary movements and nothing else. The internal Maestro staging and extraction chain is untouched. Leg A delivers into the NPS file landing area and the existing chain proceeds unchanged; leg B collects from the MWS file output area and delivers straight to ONS.

No goSC-11 not met, meaning the platform required bespoke construction per interface; or SC-01 or SC-02 not met; or a security criterion needs a waiver.
SC-11 decides it. If two structurally similar transfers cannot both be delivered as configuration against one engine, config over construction does not hold in practice and the onboarding economics behind the wider programme do not follow.
