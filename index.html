Boomi Managed File Transfer MVP

Recommended high-level delivery steps | v1.0 | Companion to Executive Concept Note Draft v0.2 | Dates intentionally excluded

How to use this page

  1. Use the download bar at the top to get the Word document (narrative for stakeholders), the Excel step tracker (working checklist) and the draw.io flow diagram. The first zip holds these three; the library zip holds every document in this repo.
  2. Read Phase overview and Sequencing first. Phases are ordered by dependency, not by date, so a plan can be built once lead times are known.
  3. Expand each phase under Steps by phase. Each has an exit gate; do not start the next dependent phase until the gate is met.
  4. In the Excel tracker, edit only the yellow columns (Status, Owner, Notes). The Phase Summary sheet calculates completion automatically.
  5. Open the diagram with Open diagram in viewer, or import the .drawio file into app.diagrams.net to edit it.
  6. Use the traceability tables to check every dependency and success criterion is covered by at least one phase.

Steps by phase

P0 Mobilise and confirm Governance

Lock the decisions and people the MVP depends on before any build starts.

  1. Confirm ADR.040/041 as the MVP candidate and record the executive decision
  2. Name owners for business, DWIT, security, network, operations, Boomi implementation and 24x7 support
  3. Confirm data classification, file naming rules, typical and peak file sizes, and quarterly schedule
  4. Record decision D7: build against current ADR endpoints, re-point to Data Lake later as a configuration change
  5. Open a RAID log and decision log with named owners; agree go/no-go criteria up front (use SC1 to SC6)
Dependencies: D5, D7, D8  |  Success criteria: -  |  Lead role: MVP Lead / Service Owner
Exit gate: Decision log signed off; owners named; file profile confirmed
P1 Environments and connectivity Platform (critical path)

Raise the long-lead infrastructure and network changes on day one.

  1. Confirm Dev, Test, Pre-prod and Prod MFT tenants and MFT CI/CD portal access
  2. Install and register organisation-hosted runtimes; confirm Windows Server hardening and Defender AV (D6)
  3. Raise firewall and allow-list changes for NPS, ADR and ONS in every environment (inbound and outbound, protocol and port)
  4. Agree with ONS the new sending endpoint, source IPs and a production-like lower environment
  5. Run a connectivity smoke test per endpoint per environment (TCP, protocol handshake, auth) and record evidence
Dependencies: D1, D2, D3, D4, D6  |  Success criteria: -  |  Lead role: Platform Engineer / Network
Exit gate: All endpoints reachable from runtime in lower environments with evidence
P2 Security and credentials Security

Make the secure-transfer controls explicit rather than assumed.

  1. Exchange SSH host keys / certificates and pin them; agree key rotation ownership
  2. Decide credential storage: native MFT vault now, or documented route to enterprise PAM (tracked gap G-14)
  3. Confirm AV scanning point and behaviour on scan failure (quarantine, alert, no onward delivery)
  4. Check feed file size against AV scan ceiling (about 250 MB, gap G-15); design split or exception if exceeded
  5. Obtain security sign-off of the transfer design for the confirmed classification
Dependencies: D2, D3, D5, D6  |  Success criteria: SC5, SC6  |  Lead role: Security Architect
Exit gate: Security design approved; credentials and keys in place
P3 Configure Leg A (NPS to ADR) Build

Configure, not construct: one transfer definition per leg driven by configuration.

  1. Define source and target endpoints, file mask and naming rules
  2. Set schedule and non-arrival window aligned to the quarterly feed
  3. Configure AV scan, archive, quarantine, retry and checksum validation
  4. Configure alerts for non-arrival, transfer failure and scan failure to a named team
  5. Parameterise environment-specific values so promotion changes config, not design
Dependencies: D1, D3, D5  |  Success criteria: SC1, SC4, SC5, SC6  |  Lead role: Boomi MFT Engineer
Exit gate: Leg A runs in Dev with a synthetic file
P4 Configure Leg B (ADR to ONS) Build

Replace the IF and SDES hop with a direct, audited external delivery.

  1. Define ADR output source and ONS external target with pinned host key / certificate
  2. Set trigger (schedule or event after Leg A processing chain completes)
  3. Configure AV scan, archive, quarantine, retry and checksum validation
  4. Agree and configure the ONS receipt acknowledgement method
  5. Configure alerts and audit record fields as per SC6
Dependencies: D3, D4, D5  |  Success criteria: SC2, SC4, SC5, SC6  |  Lead role: Boomi MFT Engineer
Exit gate: Leg B delivers to ONS lower environment with acknowledgement
P5 CI/CD promotion Build

Prove repeatable, approval-controlled promotion across environments.

  1. Package both leg configurations in the MFT CI/CD portal
  2. Define approval roles (requester, approver) and segregation of duties
  3. Promote Dev to Test to Pre-prod with environment overrides only
  4. Test and document rollback: config rows are data, so rollback is a re-promotion of the prior version (gap G-13)
  5. Capture promotion audit evidence for each step
Dependencies: D1  |  Success criteria: SC3  |  Lead role: Platform Engineer
Exit gate: Both legs promoted to Pre-prod via approved pipeline with audit trail
P6 Observability and audit Operate

Treat visibility as a feature from the first run.

  1. Confirm transfer history view covers both legs end to end
  2. Verify audit record fields: source, destination, file size, checksum, timestamps, outcome
  3. Route alerts to the named team; ServiceNow or Dynatrace only if essential for readiness
  4. Define simple service KPIs: on-time delivery, failures, mean time to recover
Dependencies: D8  |  Success criteria: SC4, SC5, SC6  |  Lead role: Operations Lead
Exit gate: Dashboards and alerts demonstrated to operations
P7 Test Assure

Evidence positive and negative paths in a production-like environment.

  1. Positive: Leg A and Leg B end to end with representative file sizes
  2. Negative: non-arrival, target unavailable, credential failure, AV scan failure, checksum mismatch, duplicate file
  3. Recovery: retry, re-run from archive, release from quarantine
  4. Promotion and rollback test via CI/CD portal
  5. Collate a test evidence pack mapped to SC1 to SC6
Dependencies: D4, D5  |  Success criteria: SC1, SC2, SC3, SC4, SC5, SC6  |  Lead role: Test Lead
Exit gate: Evidence pack reviewed; defects closed or accepted
P8 Prove in production and hand over Operate

Run the live feed and transfer ownership to the service.

  1. Promote to Prod through CI/CD with change approval
  2. Run the live quarterly transfer with hypercare and parallel check against the legacy route
  3. Decommission or disable the UTM and IF/SDES route once delivery is confirmed
  4. Hand over runbook, alert routing, support model and Boomi 24x7 escalation; run a support drill
  5. Obtain service acceptance from operations
Dependencies: D8  |  Success criteria: SC1, SC2, SC4, SC5, SC6  |  Lead role: Service Owner
Exit gate: Live feed delivered; service accepted by operations
P9 Go/no-go and scale recommendation Governance

Close the MVP with a documented decision on wider adoption.

  1. Score each success criterion with evidence
  2. Record lessons learned, open gaps (G-13, G-14, G-15) and platform constraints
  3. Define the onboarding pattern and template for the next feeds
  4. Issue go/no-go and wider adoption recommendation to the executive sponsor
Dependencies: -  |  Success criteria: SC1, SC2, SC3, SC4, SC5, SC6  |  Lead role: MVP Lead
Exit gate: Recommendation issued; definition of done met

Recommendations and risks

IDRecommendationRationale
R1Treat connectivity as the critical pathFirewall, allow-list and ONS changes take longest. Raise them in P0/P1 before configuration is ready.
R2Test file size against the AV scan ceiling earlyIf the scan file exceeds the approx 250 MB AV limit (G-15), the scan-failure path becomes the normal path.
R3Decide credential storage explicitlyNo documented native route to enterprise PAM (G-14). Record the MVP choice and the target state as a decision.
R4Document rollback for config promotionMFT configuration is data, not a build artefact (G-13). Prove rollback as re-promotion of the prior version.
R5Build against current ADR, re-point laterProving re-pointing to the Data Lake as a config-only change is itself evidence for scale.
R6Prove SFTP through any load balancer earlyProtocol-layer load balancing, source NAT and allow-lists can break external delivery to ONS.
R7Keep the legacy route warm until live proofRun the first production quarter with a fallback to UTM and IF/SDES until SC1 and SC2 are evidenced.
R8Agree the ONS acknowledgement mechanismSC2 requires acknowledged receipt; confirm what counts as an acknowledgement before build.

Additional information

  • Scope is unchanged from the concept note: two transfer legs, no content transformation, no redesign of the retained downstream job chain.
  • Gap references: G-13 (no native CI/CD rollback for config data), G-14 (no documented native PAM route), G-15 (AV scan ceiling approx 250 MB).
  • All deliverables are generated from one data file so the page, Word, Excel and diagram stay consistent.
