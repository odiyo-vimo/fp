Screen 3: Dashboard (landing page)

Manage File Transfers

This is the entry point for managing file transfers on the platform. From here you can browse what is already configured, move an approved configuration through to the next environment, and clear the approvals queue that gates those moves. The three cards below follow the lifecycle in order: see what exists, promote a change, then approve it.

MFT Transfer Catalog
Transfer Catalog

Browse existing scheduled file transfer configurations. Each entry shows its source, destination, schedule and when it last ran.

MFT Flow Promotion
Promote a Flow

Move an approved transfer configuration from one environment to the next. Raises the promotion request and tracks it through to release.

Approval - MFT flow promotion
View Approval Requests

Review outstanding promotion requests and approve or reject them. Nothing moves environment until it has been cleared here.

How to use this page

  1. Use the black bar at the top of the page to download the supporting documents. The ZIP contains every file in one download.
  2. Three screens are prototyped above. Screen 3 is the landing page users arrive at first. Screen 1 is the promotion approvals grid, where View Request raises a confirmation message rather than opening a record. Screen 2 is the transfer catalog, which is read only.
  3. To wire either screen to live data, replace the <tbody> contents with rows from the request configuration table. Keep the column order fixed. Screen 1: Actions, Name, Requested By, Requested On, Flow Name, Flow ID, From Env to To Env. Screen 2: Name, Flow Name, Source, Destination, Schedule, Last Run, Created.
  4. To lift the markup into another page, download Table snippet (HTML). It contains the table and its styles only, with no page furniture.
  5. Read the open decisions below before treating the Flow Name column as agreed. It is not present in the source screen.

Using the draw.io mockup

  1. Download Dashboard mockup (draw.io) from the bar at the top.
  2. Open app.diagrams.net, choose Open Existing Diagram, and select the downloaded .drawio file. It also opens in the draw.io desktop app and in the Confluence and Visual Studio Code draw.io plugins.
  3. The file has three pages, selectable by the tabs at the foot of the draw.io canvas: Approvals - MFT Flow Promotion, Transfer Catalog and Dashboard.
  4. Every header cell, data cell and action button is a separate shape, so rows can be added, removed or reordered without redrawing the grid. Approvals - MFT Flow Promotion: row height 32px, columns Actions 130, Name 190, Requested By 165, Requested On 165, Flow Name 150, Flow ID 100, From Env to To Env 120. Transfer Catalog: row height 64px, columns Name 180, Flow Name 140, Source 200, Destination 200, Schedule 100, Last Run 100, Created 100. Both sum to the 1020px table width.
  5. The orange panel at the foot of each page carries the open decisions for that screen. Keep it attached when circulating the mockup so reviewers see what is still unresolved.
  6. To export for a slide or a document, use File, Export as, PNG with a transparent background and 2x scale.

Reusing the styling

All styling is inline in this file, with no external dependencies or build step. Colours, the black table header and the alternating row shading follow the GOV.UK Design System conventions in the source screen. Focus states use the standard yellow focus colour so keyboard navigation stays visible.

Notes and assumptions

  • Row data is transcribed from the supplied screenshot. Original spellings, including Aprove and Beligum, are preserved deliberately so the table reflects real captured data rather than a cleaned-up version.
  • Flow ID and From Env -> To Env values are placeholders. Neither column exists in the source screen, so no real values were available. They must not be treated as confirmed until D-AP-01 and D-AP-02 are closed.
  • The table is a static front-end prototype. No Boomi Flow, API or data source is wired to it.
  • Styling follows the GOV.UK Design System conventions visible in the screenshot: Transport-style typography stack, black table header, alternating row shading, and the standard footer with OGL licensing.
