How to use this page

  1. Use the download bar at the top. The Excel workbook is the working requirement sheet (filters, drop-downs for priority and status, yellow cells for owner, comments and decisions). The two draw.io files are the editable diagrams (journey view and interaction view); each has PNG and SVG copies for slides and documents. The first zip holds these seven files; the library zip holds every document in this repository.
  2. Read the journey summaries, then the consolidated diagram. Box colour shows the system doing the work; line style shows the integration type. Step numbers in each box match the source sequence diagrams.
  3. Use the requirement filters to narrow by category or search by text, for example NRS, eDMS, file collection or a step reference such as J3 steps 18. Each requirement cites the source steps it came from.
  4. Rows marked Architect proposal (the NFR rows and EVT-13) are additions for review and are not in the source designs.
  5. Work the open items with the named owner roles before the requirements move from Draft to Agreed. Record decisions in the Open Items sheet.
  6. Read the interaction diagram top to bottom: black bars separate the journeys, numbered arrows follow the source step numbers, and red notes point to open items. Use Actual size and scroll, or Fit to width for an overview.
  7. To edit either diagram, open its .drawio file in diagrams.net or the draw.io desktop app, or use the viewer buttons in the download bar.

Consolidated from draft design pages (see Sources). Where the drafts disagree or leave a gap, the item is logged under Open items rather than resolved here. Download links work on the GitHub Pages site; when this page is viewed inside a chat preview, use the file cards in the chat instead.

Journeys

Three journeys. NRS submission and eDMS ingestion run as parallel legs inside Journey 3; Journey 1 step 45 reuses the eDMS leg for thread attachments.

  • J1

    Create Thread

    Actor: Internal user (thread owner)

    Trigger: Internal user selects Create Thread in the workspace (already authenticated and authorised to create threads)

    Outcome: Thread in pending status with technical and business reference; attachments passed to eDMS; recipient notified (proposed)

    HIP involvement: File upload per attachment (separate File Upload sequence, pattern TBC); eDMS transfer at step 45; thread confirmation event (proposed)

    Recipient (external user) is asked to provide documents: leads into J2

  • J2

    External User Document Upload

    Actor: External user

    Trigger: External user selects documents to upload against a thread interaction

    Outcome: Documents clean-staged in HIP (or quarantined); session, interaction and document state updated; user notified

    HIP involvement: File Transfer API, pre-signed URL generation, landing bucket, AV scan, quarantine, clean staging, upload outcome events

    Clean-staged documents are referenced by the submission: leads into J3

  • J3

    External User Submission (crystallisation)

    Actor: External user; Internal user notified

    Trigger: External user clicks submit on the interaction response

    Outcome: Signed submission with attachments held by NRS (evidential) and ingested by eDMS; both users notified; staged files deleted

    HIP involvement: NRS Submission and Attachment APIs via API Management; file transfer request queue; transfers to NRS and eDMS; transfer, acceptance and deletion events

    End of journey
