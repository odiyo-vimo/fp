1. Solution overview

Boomi MFT takes over the two boundary movements of feed ADR.040 and nothing else. The internal Maestro chain that stages and extracts the data inside ADR is untouched. Leg A collects the source extract and delivers it into the NPS file landing area, at which point the existing chain proceeds exactly as it does today. Leg B collects from the MWS file output area and delivers directly to ONS, removing the Insecure IF server hop.

In scopeTwo transfer flows, delivered as configuration rows consumed by the existing generic engine process. No bespoke Boomi component is created for either leg.
Out of scopeAny change to the Maestro job chain, to the file content or schema, or to the business meaning of the feed. No decommissioning of UTM, the IF server or SDES.
Design principleConfig over construction. Everything in sections 3 to 14 becomes a value in a configuration row, not a line of code.
ClassificationOFFICIAL. The file is assumed to contain personal data until section 7 confirms otherwise.
