1. Summary

The consumer calls the EDMS endpoint published on Boomi CAM. CAM applies gateway policies and routes the call to the Boomi iPaaS integration process. iPaaS validates the Microsoft Entra ID access token, validates and splits the composite documentId, and calls Doxis through the Doxis adapter. When Doxis returns the metadata and content stream, iPaaS checks the caller with the SCR Broker and decides whether the caller may see the document. An authorised caller gets a multipart/mixed response streamed end to end; anyone else gets the same 404 as a missing document.

2. Sequence

Yellow boxes are processing inside a component. Solid arrows are requests, dashed black arrows are responses, dashed red arrows are error exits. Error responses go back through Boomi CAM; they are drawn direct to the consumer to keep the diagram readable.

PC6Resolve the requested content object or use the primary content object when contentObjectId is omitted.Doxis10
PC7Retrieve normalised metadata and stream content end to end without Base64 encoding or buffering the complete file.Boomi iPaaS, Boomi CAM11, 12, 16, 17
PC8Return the same 404 response for a missing document and a document the caller is not authorised to see.Boomi iPaaS11a, 19
PC9Check the caller's SCR certification through the SCR Broker before any content is released; fail closed if the broker cannot answer.Boomi iPaaS, SCR Broker13 to 19

PC1 to PC8 are from the interface specification. PC9 is added for the SCR Broker check described for this journey.

6. Success response

HTTP/1.1 200 OK
Content-Type: multipart/mixed; boundary=edms-boundary
X-Correlation-ID: 7d1c...

--edms-boundary
Content-Type: application/json

{ ...EdmsMetaDataResponse (normalised metadata)... }
--edms-boundary
Content-Type: application/pdf            (resolved document MIME type)
Content-Disposition: attachment; filename="..."

<binary stream, not Base64 encoded>
--edms-boundary--

The metadata part is written first so the consumer can read it before the binary part arrives. Content-Length is not known up front, so the response uses chunked transfer.
