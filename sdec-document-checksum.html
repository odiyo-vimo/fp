1. What a checksum is

A checksum is a short, fixed-length fingerprint calculated from every byte of a file. The SDEC upload uses SHA-256, which always produces 32 bytes (256 bits), whether the file is 1 KB or 20 GB.

DeterministicThe same bytes always give the same value, on any machine.
SensitiveChanging one bit, or dropping the last byte, gives a completely different value.
One-wayThe file cannot be rebuilt from the value, so the value holds no document content.
Collision resistantIt is not practical to make a different file with the same value.

Common defect: Base64 encoding the 64-character hex string instead of the 32 raw bytes. That gives an 88-character value (Yjk0ZDI3Yjk5MzRkM2UwOGE1...) that never matches. A valid checksumSha256 is always 44 characters and ends in =.

2. Why it is needed when TLS is already used

TLS protects each connection. It does not prove that the file stored at the end is the file the user selected at the start. The document crosses several hops and rests in transient storage between them; one checksum, created once in the browser, is checked at each point.

  • Truncated large uploads. A 20 GB stream that drops early can reach the server as a shorter body. The digest shows it is incomplete.
  • File changed after selection. If the user edits or replaces the file on disk after step 1, the upload no longer matches what was registered.
  • Corruption at rest or in copy. A storage or copy fault in transient storage is caught before delivery to NRS or eDMS.
  • Wrong file on a valid URL. The digest is part of the signed presigned URL, so the URL only accepts the one file it was issued for (S-06).
  • Evidence of receipt. NRS can show it holds exactly the bytes the user submitted, which supports audit and dispute handling.

A checksum on its own does not prove who sent the file, because anyone can calculate SHA-256. The URL signature covers the digest, and that is what ties the content to an authorised request.

4. Sequence: checksum through upload and delivery

Three flows: a matching upload, a mismatch with re-try, and the onward transfer to NRS where the same digest is checked again.

Rule for every case: a file whose digest does not match is never set to UPLOADED or AVAILABLE and is never released to NRS or eDMS (S-08, A-08).

6. Build notes by delivery group

SDEC browser

  • Use a streaming SHA-256 that reads the file in chunks (for example 32 MB). Web Crypto crypto.subtle.digest needs the whole file in memory, so it is not suitable for files up to 20 GB.
  • Run the hash in a Web Worker and show progress. A 20 GB file is read twice (hash, then upload), and hashing alone can take several minutes on a typical laptop.
  • Encode the 32 raw digest bytes as Base64. Never encode the hex string.
// Example with the hash-wasm library (incremental SHA-256)
import { createSHA256 } from 'hash-wasm';

async function sha256Base64(file, chunk = 32 * 1024 * 1024) {
  const h = await createSHA256();
  h.init();
  for (let pos = 0; pos < file.size; pos += chunk) {
    h.update(new Uint8Array(await file.slice(pos, pos + chunk).arrayBuffer()));
  }
  const bytes = h.digest('binary');            // 32 raw bytes
  return btoa(String.fromCharCode(...bytes));  // 44-character Base64
}

SDEC backend

  • Pass checksumSha256 through unchanged and store it against externalDocumentId for reconciliation. The backend never sees file content (A-03), so it cannot recompute it.

iPaaS

  • Store the expected digest with the fileId and include it in the HMAC signing input for the presigned URL.
  • Calculate SHA-256 incrementally while streaming the body to /inbound; compare before setting UPLOADED. On mismatch, delete the partial file.
  • Keep the computed digest in the document status record so SDEC-MFT-API-02 can return it.
  • Re-verify before transfer to NRS and eDMS (scope under D-21). Digest values hold no personal data and can be logged; document names stay masked (S-12).

NRS

  • Accept checksumSha256 in the attachment request (SDEC-NRS-API-02) and verify it on receipt. Support to be confirmed under D-11 and D-21.
